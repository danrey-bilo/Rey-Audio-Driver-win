# Rey Audio Driver 2.7.0 preview

Служба управляет независимыми сессиями по постоянному DeviceId. Выбор карты
вверху панели меняет только отображение. Для каждой карты 8×8 код ACX создаёт
четыре стереопары и полный многоканальный интерфейс в каждом направлении.
[Устройства Windows и использование](ENDPOINTS.ru.md).

![Микшер с обнаруженной реальной Pi](assets/rey-mixer.png)

## Структура

| Модуль | Задача |
|---|---|
| `service/manager` | Каталог карт, сопоставление ID, выбор отображения, обнаружение USB и проверка LAN-портов |
| `service/device_session` | Отдельный worker, транспорт, повтор подключения, микшер, счётчики и события одной карты |
| `service/device_store` | Проверенные ID, профили карты в реестре, выбранное отображение и удаление офлайн-профиля |
| `service/commands` | Общий строгий разбор команд настроек |
| `audio/mixer` | Фиксированные буферы, атомарные уровни, индикаторы и плавное изменение усиления |
| `engine/usb_session` | Открытие конкретного USB-пути и проверка ID без попытки открыть остальные активные карты |
| `drivers/Acx/device` | До десяти дочерних устройств, отдельный служебный handle на карту, контейнеры и асинхронное удаление |
| `drivers/Acx/circuit` | Отдельные пары/полные circuits, маски каналов и режимы RAW/default/communications/media/movie |
| `drivers/Acx/stream` | Собственные WaveRT-слоты и позиции endpoints; ограниченная PCM-операция под блокировкой своей карты |
| `include/piaoip/endpoints.h` | Общий разбор каналов и ограничение PCM по разрядности, используемые нативными тестами |

Общая блокировка владельцев освобождается до обработки PCM; у каждой карты
своя блокировка. Закрытие её служебного handle удаляет только её дочернее
устройство. Все входные пары читаются до перезаписи совмещённого IOCTL-буфера
ответом воспроизведения. Выходы полной карты и пар суммируются в каналы карты.
Дополнительная PCM-очередь не добавляется. Отмена операций, PnP и жизненный
цикл ядра ещё требуют проверки Driver Verifier на подготовленном ПК.

64-битный реестр: `HKLM\Software\ReyAudio\Devices\<ID из 32 символов>\Profiles`.
Каждая карта сохраняется отдельным ограниченным значением RYS1/v2 с профилями
и микшером. `SelectedDevice` отдельно хранит выбор отображения. Старые настройки
одной карты переносятся на первую сопоставленную карту; остальные получают свои
профили. Консольные тесты используют изолированные бинарные файлы с тем же
форматом. Пользователь работает через панель; INI и автоматического подбора
буферов нет.

`DEVICE <ID> <команда>` явно адресует карту; `SELECT <ID>` сохраняет только выбор
отображения. `ADD_LAN` читает идентификатор до сопоставления. Одна Pi с одинаковым
ID по USB и LAN имеет одну сессию и один активный транспорт; настроенный LAN
имеет приоритет. При недоступном выбранном LAN идут повторные подключения;
автоматического переключения на USB нет. Смена маршрута/активного профиля
перезапускает только свою сессию. Правки микшера и выбор отображения этого
не делают.

| Выбор другой карты | 30 с; пройден | Одна реальная Pi и один сохранённый офлайн-профиль; не две физические карты |
| WPF | 1120×800; все восемь полос видны | Фактическая служба и реальная Pi; отсутствие драйвера показано |
| Kernel-пакет | INF и каталог проверены | SYS собран, не загружен |
| MSI/EXE | ICE, хеши семи файлов, встроенный MSI и launch conditions проверены | Установка/repair/uninstall с повышением пока не подтверждены |
| Локальная подпись | SYS/CAT подписаны, состав каталога проверен, ключ удалён, повреждённый SYS отклонён | Тест не менял доверие системы и настройки загрузки |

Отчёты: [служба](evidence/rey-manager-cards.json),
[выбор микшера](evidence/rey-card-selection.json),
[установщик](evidence/rey-installer-cards.json), [панель](evidence/rey-cards-ui.json).

Среднее время цифрового callback в снимках службы: **0,45–1,36 мкс**;
максимальный снимок: **168,9 мкс**. Пропущенных кадров нет. Во всех итогах USB
нет layout underrun/overrun и USB errors. Самый длинный сегмент — 51,814 с,
максимальная пауза приёма **1522,4 мкс**. Отдельный поток с выбором офлайн-карты
работал 29,828 с: 229665 callbacks, 5511960 кадров, максимальная пауза
**574,8 мкс**, те же нулевые ошибки. Это результаты обработки и непрерывности,
не RTT и не физическая задержка звука. Процентили пауз и загрузка CPU в этих
функциональных тестах не собирались.

Предыдущий цифровой тест транспорта остаётся отдельным результатом: 299 с,
8×8/192 кГц/PCM32/depth3, RTT p50/p95/p99/max 373/410/419/944,2 мкс.
Для физического USB round-trip <2 мс нужны загруженные Windows endpoints,
backend с независимым аудиотактом и аппаратная петля ADC/DAC. Отдельные карты
пока не образуют синхронизированный агрегированный интерфейс.

## Сборка и установка

[Инструкция MSI/EXE](INSTALL.ru.md). Установщик сохраняет бесплатную уникальную
локальную тестовую подпись. **Нужен Test Mode Windows.** Secure Boot и
перезагрузка — явные действия пользователя. MSI не выключает изоляцию ядра.
Разработческие проверки не готовят Windows и не устанавливают драйвер скрыто.

Порядок CMake/WDK/WiX сохранён в [руководстве сборки](REY-AUDIO-2.6.ru.md).
После сборки выполните `ctest --output-on-failure`. Ограниченные консольные
проверки — `tools/test_manager.py` и `tools/test_card_selection.py`; они не
устанавливают драйвер. Установщику на клиентском ПК не нужны внешние инструменты
подписания. Pi4 и USB-протокол не менялись.
