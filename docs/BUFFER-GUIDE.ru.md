# Ручные буферы USB-ASIO

Блок ASIO: 16, 32, 64, 128, 256 кадров. Запас отправки: 1–4 блока.
Очередь USB: 1–16 пакетов. Значения независимы, меняются вручную;
автоматического выбора «самого быстрого» режима нет.

Контрольные профили 2.8.1 для 96/192 кГц описаны в
[отчёте низкой задержки](USB-LATENCY-2.8.1.ru.md). На Pi нужен обновлённый
USB runtime с FIFO 40 и блокировкой памяти; одной смены буфера в Windows недостаточно.

Примеры расчёта при USB depth4:

| Частота / блок / lead | Заявленная сумма |
|---|---|
| 192 кГц / 64 / 3 | 1,5052 мс |
| 192 кГц / 64 / 4 | 1,8385 мс |
| 96 кГц / 32 / 3 | 1,5104 мс |
| 96 кГц / 32 / 4 | 1,8438 мс |

Это значения из ASIO getLatencies, а не измеренная аналоговая петля.
Меньший буфер сокращает время на пробуждение host и повышает риск пропусков.
При меньшей частоте тот же блок длится дольше. Прежние короткие успехи 16/32
не доказывают стабильность; испытания прежней сборки содержали ошибки.
[История 2.8.0](USB-ONLY-2.8.ru.md) сохранена отдельно от новых замеров.

Настройки → ASIO → «Сохранить», затем заново откройте драйвер в Ableton. Очередь,
частота и PCM применяются отдельно кнопкой «Применить» в разделе «Формат аудио» после закрытия ASIO.
Проверяйте свой проект, число пропусков/опозданий, переполнение, непрерывность
кадров и RTT. Один прогон — 175 секунд, с завершением до трёх минут. Хорошая медиана при пропусках
не означает стабильный профиль. Перед сравнением проверяйте generation и
connection_id. Уменьшение depth2 уже давало замедление цифрового стенда;
нулевого счётчика ошибок для выбора недостаточно.

Запас ASIO и очередь USB находятся в «Дополнительно» соответствующих карточек.
