# Буфер ASIO и автоматические настройки USB

Выбирай **буфер ASIO** в DAW или панели Rey. Глубину USB и запас render драйвер
задаёт сам для каждой частоты. Старые ручные настройки очереди/запаса не
используются. 384 кГц не предлагаются.

ASIO16 соответствует периоду JACK32: это профиль проверки минимальной задержки.
Периоды JACK128/256 используют отдельный запас приёма на измеренные паузы и
пакетную выдачу ПК. Это добавляет запас и задержку; политика JACK32 не меняется.
Для более тяжёлых проектов можно увеличить буфер. В
[отчёте USB/JACK](USB-LATENCY-2026-10-16.md) указаны точный размер и длительность
проверок; результат отдельной DAW нужно проверять на её проекте.

Интервал USB — 125 мкс. Одновременно ожидают восемь запросов capture и два
запроса render по четыре пакета. Группировка записи не меняет интервал
отдельных пакетов на 500 мкс или 1 мс. Запас render — 333 мкс, при 192 кГц —
500 мкс, с округлением до блоков ASIO. Для 192 кГц он покрывает всю группу
пакетов перед ожиданием хоста.

Native ASIO следует такту AKM/JACK через число отсчётов в пакетах, без
пересчёта PCM во времени. Очереди Pi и физический I/O также добавляют задержку.
Переключения на UAC2/WASAPI в службе нет.
Движок float не заявляет bit-exact PCM32.

Если быстрых физических ядер достаточно и пользователь не задал ограничения,
служба и поток ASIO получают разные пары ядер CPU Sets с миграцией внутри пары.
Ограничения процесса/потока и явные диагностические привязки сохраняются.
Глобальные настройки процессора и питания Windows не меняются.
В активном потоке служба до 75 мкс проверяет завершение USB перед ожиданием
события. Это увеличивает нагрузку одного ядра; измеренная цена есть в отчёте.

getLatencies и панель показывают буферы ПК, а не измеренную полную задержку
Pi/АЦП/ЦАП. Проверяй счётчики на обеих сторонах: чистый результат ПК может
не показать недостачу кадров внутри Pi. Для физического времени преобразователей
нужна отдельная аналоговая петля.
