# Rey Audio Driver 2.6.0: USB, AoIP и новая панель

В этой версии одна фоновая служба управляет двумя отдельными транспортами:
USB и AoIP/LAN. Панель и служба собираются без ASIO SDK. Поддерживается один Pi5;
несколько физических устройств пока отложены.

## Что реализовано

| Компонент | Работа |
|---|---|
| Rey Audio Service | Автозапуск Windows, поиск USB, повторное подключение, одна активная сессия |
| Панель и трей | Отдельные USB/LAN страницы и настройки, реальные состояния службы, диагностика |
| USB | 8 входов + 8 выходов, PCM16/24/32, 44,1–192 кГц; HS interrupt, WinUSB, overlapped I/O |
| AoIP | Существующий UDP/IPv4/IOCP движок, ручные block/guard/packet, экономия во время тишины |
| Собственный ACX | Root bridge, динамический child, вход/выход, имена Rey; SYS/INF/CAT собраны и проверены |

**ACX не подписан, не установлен и не проверен через WASAPI.** Установка службы
показывает устройство и позволяет сохранить настройки, но системные звуковые
входы/выходы появятся только с установленным собственным аудиодрайвером. Панель
отображает это ограничение явно. USB backend Pi пока возвращает цифровые PCM
данные; подключённый ADC/DAC, аппаратный такт и физическая задержка не проверены.
Пакет выпускается как Pre-release.

## Как пользоваться

USB появляется автоматически. Служба раз в секунду перечисляет только наш GUID
интерфейса, не открывая занятую USB-сессию. При открытии проверяются HS-дескриптор
и стабильный DeviceId платы. Отключение и возврат USB проверены остановкой/запуском
только собственной gadget-службы Pi. Вынимание питающего кабеля и sleep/resume
Windows отдельно не испытывались.

Для LAN откройте трей → **AoIP / LAN**, найдите Pi или введите IPv4-адрес и
нажмите **Подключить LAN**. Подключённый LAN имеет приоритет по умолчанию.
**Использовать USB** выбирает USB явно. Перед сменой служба останавливает и
освобождает прежнюю сессию. Переход прерывает поток; бесшовное переключение
не заявляется. Автоматического перехода с недоступного LAN на USB пока нет:
нужно отключить LAN или выбрать USB; LAN-сессия иначе повторяет подключение.

Настройки `[USB]` и `[AoIP]` независимы, сохраняются в
`%ProgramData%/ReyAudio/service.ini`. Изменение профиля неактивного транспорта
не перезапускает активный поток. Неверные значения не изменяют сохранённый
профиль. Автоматического подбора буферов нет. USB частота/разрядность задаются
в его разделе; LAN получает формат от Pi, который настраивается на самой плате.

Начальная отправная точка LAN — block256/guard1536/packet32 из предыдущего
цифрового теста. Это не универсальная гарантия задержки. USB начинает с очереди
3 пакета. Подпись «запас очереди» означает её расчётный размер, а не RTT.
Раздел диагностики показывает callback gaps и текущие/последние счётчики,
которые также не являются сквозной аудиозадержкой.

Панель выполнена на WPF: современная светлая рабочая область, боковая навигация,
отдельные карточки устройства/формата, дополнительные настройки под раскрытием,
прокрутка, изменение размера окна и клавиатурный фокус. Основной язык первой
версии — русский. Закрытие окна оставляет панель в трее. **Выход из панели**
завершает только панель; служба работает независимо.

## Установка службы и панели

Распакуйте ZIP и из PowerShell администратора выполните:

```powershell
./tools/install_rey.ps1 -Package C:/work/Rey-Audio-Driver-2.6.0-preview-x64
```

Скрипт проверяет hashes трёх EXE, устанавливает их в
`%ProgramFiles%/Rey Audio Driver`, сохраняет существующую конфигурацию,
создаёт автоматическую `ReyAudioService`, задаёт recovery и запускает её.
Панель запускается в трее при входе пользователя. Служба работает от SYSTEM,
поскольку kernel control interface защищён; панель работает без повышения прав.

Правило firewall ограничено программой службы, UDP50021, Private-профилем
и LocalSubnet. Если вручную изменить локальный UDP-порт, понадобится отдельное
подходящее правило. Public-профиль не открывается.

Удаление только своих службы, автозапуска и правила:

```powershell
./tools/install_rey.ps1 -Package C:/work/Rey-Audio-Driver-2.6.0-preview-x64 -Remove
```

Файлы и настройки остаются для возврата. Скрипт не меняет test signing/boot
security, не перезагружает ПК и не устанавливает kernel-драйвер. Для уже
подготовленного драйверного стенда root ID — `Root\ReyAudioAcx`.
До производственного выпуска нужны подпись, поддерживаемая WDK/MSVC сборка,
Verifier, kernel cancellation, WASAPI/DAW и физический ADC/DAC.

## Код и проверки

| Каталог | Назначение |
|---|---|
| `src/service` | Настройки, владение сессией, выбор транспорта, локальное управление |
| `src/engine` | Общий PCM-контракт, отдельные LAN/USB движки |
| `src/bridge` | Ограниченный обмен PCM с ACX по версионированному контракту |
| `apps/ReyAudioControl` | WPF разметка, состояние, IPC-клиент, трей |
| `drivers/Acx` | Root/child, circuits и WaveRT |
| `tests`, `tools` | Контракты, конечные проверки на устройстве, сборка и упаковка |

Аудио не передаётся через управляющий pipe. Callback не захватывает mutex
менеджера. Pipe локальный, с одним экземпляром, DACL для SYSTEM/admin/interactive
user, запретом remote clients, bounded messages и отменой/завершением I/O.
Ввод принимает только фиксированные команды и проверенные значения; запуска
произвольных команд или выбора файлов из панели нет. Клиент подтверждает чтение
ответа, чтобы disconnect не выбросил ещё не прочитанные данные.

Сборка: C++17, Windows x64 SDK, .NET Framework 4.8 и PowerShell. Команда без ASIO
и карта модулей приведены в [английской инструкции](REY-AUDIO-2.6.md#build-and-structure).
USB-библиотека находится отдельно в [Pi5-AUSB](https://github.com/danrey-bilo/Pi5-AUSB).
Репозитории библиотек сохраняют свою видимость и лицензии.

Семь service contract tests прошли. На Pi проверены отсутствие драйвера как
отдельное состояние, USB discovery при эксклюзивном потоке, изменение неактивного
LAN без остановки USB, неверные команды, три изменения формата и pause/restart.
WPF снимки получены реальным рендерингом панели со статусом работающей службы.
[JSON проверки](evidence/rey-manager.json), [USB переподключение](evidence/rey-hotplug.json).

USB прошёл все 18 цифровых профилей. Ранее в 299-секундном 8×8/192000/32 тесте
получен **цифровой RTT p50/p95/p99/max 373/410/419/944,2 мкс**, без invalid packets,
missing frame indices и wait timeouts. В отчёте сохранены точные binaries этого
измерения; сборка после переименования и добавления hotplug проверяется отдельно.
[Полный USB-отчёт](https://github.com/danrey-bilo/Pi5-AUSB/blob/main/docs/RESULTS.ru.md).

Windows менеджер обслуживает только одну свою сессию. Pi gadget использует
лабораторный lock, а не общий аппаратный lease с LAN; общий владелец ADC/DAC и
feedback независимого такта остаются следующей работой. Прямой kernel USB→ACX
путь также пока не реализован: используется WinUSB-служба. Pi4 не изменён.
