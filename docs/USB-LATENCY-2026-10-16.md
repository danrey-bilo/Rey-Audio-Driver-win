# AKM USB / ASIO — dev.5, 2026-10-16

Цифровая петля **ПК → настоящий USB → JACK на Pi → USB → ПК**,
Raspberry Pi 5 / PREEMPT_RT `6.18.50+rpt-rpi-v8-rt`, AK5538VN / AK4458VN.
JACK работает от тактового генератора AKM. АЦП/ЦАП и эффекты в измерительную
петлю не включены; генератор отключён. Это конечные прогоны, без DAW soak.

## Результат

PCM32, 8×8, ASIO **16**, период JACK **32**. По **175 секунд** на частоту;
маркеры запускаются после готовности соединений, не раньше пяти секунд от старта измерителя.
Все маркеры вернулись, p99 по позициям PCM ниже **5 мс** на всех шести частотах.
Предыдущий прогон 88,2 кГц без маркеров был отклонён. Трассировка выявила
зависание libjack при открытии клиента одновременно с перезапуском JACK.
Добавлено подтверждённое закрытие USB/JACK-клиентов до смены профиля и возобновление
после готовности сервера. Затем все шесть частот проверены заново одними бинарными
файлами. Неподвижный устаревший статус Pi также отвергается анализатором.
Дополнительная проверка ASIO256 при 192 кГц выявила 37 недостающих кадров
внутри Pi, незаметных по маркерам ПК. Для периодов от 128 добавлен запас
на измеренный разрыв планировщика; малый профиль не менялся. После этого
вся шестичастотная серия снова выполнена окончательными бинарными файлами.

## Счётчики и нагрузка

Во всех принятых прогонах нулевые: missing/invalid/duplicate, capture drops,
render late/missing/overflow, backwards positions, MMCSS failures; USB layout
underflow/overflow/errors; Pi receive/send underflow/overflow, conversion errors,
активные JACK xruns и lease timeouts. Счётчики проверены с обеих сторон.
Короткие удачные замеры с потерями внутри Pi были отклонены.

Нагрузка — проценты **одного логического ядра**, не всего процессора.
Windows: весь прогон; Pi: участок после шести секунд подготовки.
Последний столбец — xruns при построении тестового графа; после подготовки
`steady_xruns=0`. Это отдельный счётчик, он не скрыт в нулевых результатах потока.

## Изменение транспорта

Убраны два ASRC и многомиллисекундные промежуточные очереди. Число отсчётов
в USB-пакете следует физическому такту JACK, без пересчёта PCM во времени.
Преобразование через float остаётся: bit-exact PCM32 не заявляется.

Интервал USB — **125 мкс**, восемь запросов capture; render отправляется
двумя запросами по четыре пакета. Группировка записи сохраняет интервалы
отдельных пакетов. Запас ASIO — 333 мкс, при 192 кГц — 500 мкс,
с округлением до блоков. Он покрывает пакетную группу перед ожиданием хоста.
Пользователь выбирает буфер ASIO; число запросов и запасы — внутренняя политика.

Завершённые capture-пакеты сначала целиком публикуются потоку ASIO, затем
собирается render. Ожидание render больше не задерживает уже готовый capture.
Новые пакеты для этой группы не ожидаются; дополнительной очереди нет.
Перед переходом к ожиданию события служба не более 75 мкс проверяет завершение
текущего USB-запроса. Это выполняется только в активном потоке и увеличивает
нагрузку одного ядра; значения нагрузки приведены выше.

При периоде JACK32 receive prime составляет 104/120/192/224/416/480 кадров
для частот по порядку; send target — 34/26/76/76/131/136. Старт 44,1/48/192 кГц
может добавить ведущую тишину, сохраняя все входящие кадры по порядку.
При периодах 128/256 receive сохраняет минимум 3,5 мс и дополнительный
период; целевой первоначальный запас — не менее четырёх периодов. Это отдельная
политика больших буферов, повышающая их запас и задержку.
Ожидание render на ПК ограничено одним интервалом 125 мкс; просроченные
кадры учитываются. На ПК с достаточным числом быстрых ядер двум аудиопотокам
выделяются разные пары физических ядер, с миграцией внутри каждой пары.
Существующие ограничения процесса/потока не заменяются. Используются
[Windows CPU Sets](https://learn.microsoft.com/en-us/windows/win32/procthread/cpu-sets);
глобальные настройки Windows не меняются.

JACK работает асинхронно, что устраняет срывы при построении разделённых USB
клиентов. Физический playback добавляет один период; аналоговая задержка не измерена.
Выше 96 кГц доступен только режим аудиокарты, эффекты отключены. 384 кГц
не объявлены. Комбинированный/автономный процессор: 44,1–96 кГц.

## Воспроизводимость

Pi5-AUSB 0.3.0: `5bd4fc920e43869e06893f7da8fe7f2a4e97942b`
(изменения аудиокода в `2f9de11`, следующий коммит обновляет только README).
Код Windows: `73e4b0b3c1fb7925dca96ba11b1f50987e182998`.
Код Linux: `3d113a0254fdff1a1a70544b76f1cefa01301e9d`.
Windows измерялся из изолированной сборки того же кода с отдельным IPC;
на Pi использовались конечные ELF из согласованного пакета через временные unit overrides.

Прошли 39 Windows CTests, 10 ARM64 CTests, транспортные CTests (7 Windows / 8 Linux),
72 виртуальных сценария отклонения такта. Отдельная синтетическая JACK-проверка
новых портов: пять режимов/маршрутов, 1 536 000 сравнений, ноль ошибок/xruns.
CI транспортной библиотеки, веба/хоста Linux и панели Windows проходит.

UAC2 полностью исключён из действующего аудиопути: gadget содержит только
`acm.rey_control` и `ffs.rey_asio`, Windows обнаруживает WinUSB и CDC без MEDIA
интерфейса. В службе Windows удалён UAC2/WASAPI fallback, на Pi нет запуска
ALSA/JACK USB-адаптеров. Девять Python-контрактов проверяют конфигурацию и статус.
Системный звук Windows без ASIO здесь не предоставляется.
См. [архитектуру AUSB](AUSB-NATIVE.md).

Пакет dev.5 требует согласованных Windows/Pi компонентов. Проверка целостности
и синтаксиса установщика не равна проверке применения/отката. Состояние установки
и хеши поставки фиксируются отдельно; dev.4 сохраняется для возврата.
USB-C→USB-C выключение Pi не исправлено; испытан USB-A→USB-C прямо в ПК.
