# AKM USB / ASIO — qualification, 2026-10-16

Development build `2.8.2-akm-dev.4`, Raspberry Pi 5 / ARM64 PREEMPT_RT
`6.18.50+rpt-rpi-v8-rt`, AK5538VN / AK4458VN clocked JACK backend.

Проверена **цифровая петля ПК → настоящий USB → JACK на Pi → USB → ПК**.
Аналоговые АЦП/ЦАП в петлю не включены. Генератор пользователя отключён.
Это ограниченные по времени прогоны, а не многочасовой тест DAW или аналогового тракта.

## Закреплённые настройки

Частоты аудиокарты: **44,1 / 48 / 88,2 / 96 / 176,4 / 192 кГц**.
Для комбинированного/автономного процессора — только первые четыре.
384 кГц не предлагаются приложениями и USB-дескрипторами.
Пользователь выбирает частоту, PCM и ASIO 16/32/64/128/256; ручных очередей и запасов нет.

| кГц | Запросов USB | Запас отправки Windows, мкс | Половина FIR Zita |
|---|---:|---:|---:|
| 44,1 | 8 | 1000 | 64 |
| 48 | 8 | 1000 | 32 |
| 88,2 | 8 | 750 | 16 |
| 96 | 8 | 750 | 16 |
| 176,4 | 8 | 1500 | 16 |
| 192 | 8 | 1500 | 16 |

Интервал USB — 125 мкс. Запас приёма Pi: **max(3 периода JACK, 5 мс)**;
отправки: **max(2 периода, 2 мс)**. Ресемплеры согласуют независимые часы AKM и USB.
Используется float: режим не обещает побитовую передачу PCM32.
Численная проверка выбранных FIR на 20 кГц дала +0,00241 дБ при 44,1 кГц,
+0,00067 дБ при 48 кГц и около −0,00012 дБ при 88,2 кГц.
Это проверка цифрового фильтра, не АЧХ всей аналоговой платы.

ASIO getLatencies и подсказка панели пока описывают очереди **ПК**.
Они не включают всю задержку Pi/ASRC/JACK/АЦП/ЦАП; для полной компенсации DAW
нужен отдельный замер аналоговой петли. Значение 125 мкс не равно сквозной задержке.

## Что исправлено

* Native backend 2 подключён к JACK: `rey_usb_native:capture_1..8` и `playback_1..8`.
  Backend 1 сохранён как отдельный цифровой echo. UAC2 остаётся совместимым путём
  обычного звука Windows, освобождаемым на время native ASIO.
* Отдельные часы USB/AKM согласуются заранее созданными VResampler и ограниченными FIFO.
  Callback не обращается к файлам и не выделяет память. Supervisor работает на CPU3,
  USB — CPU0, JACK callback — CPU1; глобальная политика ядер не переписывалась.
* Гонка unsigned timestamp больше не завершает живой поток по ошибочному lease timeout.
  [WinUSB FlushPipe](https://learn.microsoft.com/en-us/windows/win32/api/winusb/nf-winusb-winusb_flushpipe)
  очищает кэш, но оставшийся пакет устройства тоже нужно убрать: до первого нового
  OUT выполняется ограниченное чтение старого IN с ожиданием 10 мс. Во время аудио
  пакеты не отбрасываются. Отдельная серия проверяет повторные открытия PCM16/24/32.
  Полный 32-битный epoch не усекается
  до старого 16-битного тега необязательного мостика.
* Кольца ASIO увеличены до 64 позиций, IPC ABI 2. Пакетная выдача Windows не отбрасывается
  как устаревшая. Предпочтительное ядро допускает миграцию при занятости процессора.
* Панель ожидает текущую автоматическую смену профиля, повторно подключает только
  чтение статуса и не переотправляет неоднозначную команду изменения.
* USB CDC закрывается при unbind: снятие gadget больше не ждёт открытый ttyGS0.
  Постоянная native-служба отделена от перезапусков JACK и имеет ограничения доступа.

Отброшены варианты: ALSA с двумя периодами (xrun), слишком короткие FIR на 44,1/48 кГц
(завал на 20 кГц), запас RX 4 мс с узким servo (54 потерянных сэмпла на Pi),
жёсткая привязка Windows к одному ядру (пауза callback около 17 мс).
При 96 кГц / 256 два периода RX дали один недостаток 12 сэмплов, не замеченный
разреженными маркерами ПК. Поэтому итоговый файл использует три периода;
его отдельный прогон 256 включён в таблицу выше. До последней правки открытия
Windows тот же native ELF также прошёл 175 с на 96 кГц / 256 без ошибок Pi/ПК.
Итоговое открытие отдельно проверено шестью 12-секундными маркерными прогонами
с изменением частот/PCM и двадцатью короткими тихими start/stop. Последние
проверяют запуск и целостность счётчиков, не задержку или содержимое аудио.
Неуспешные варианты не объявлены стабильными.

После исходных прогонов пользователь подтвердил постоянную установку новых
I/O/worker/native-компонентов Pi и Windows-пакета. Установка и минутный тихий
поток прошли успешно: [проверки установленной системы](USB-INSTALLATION-2026-10-16.md).

## Reproduce the digital scope

Use the coordinated Pi/Windows builds and an otherwise idle ASIO host. Compile
the target-side helper from the Linux repository:

```sh
c++ -O2 -std=c++17 native/test_usb_transport_loop.cpp -o build/rey-test-usb-loop -ljack -pthread
sudo systemd-run --wait --pipe --collect --unit=rey-usb-loop-check --uid=rey-effects --gid=audio \
  -p RuntimeMaxSec=185 -p LimitRTPRIO=45 -p LimitMEMLOCK=268435456 -p CPUAffinity=1 \
  --setenv=JACK_DEFAULT_SERVER=rey-effects /opt/rey-effects/build/rey-test-usb-loop --native-loop 180
```

While the helper waits for the native ports, run the Windows probe against the
coordinated driver: `ReyAsioProbe.exe --registered --pulse-loop --seconds 175 --block 16`.
The recorded runs instead used `--dll` with the isolated qualification DLL.
Inspect both probe output and `/run/rey-effects/usb-native-status.json`; a clean
host marker result alone does not prove clean Pi FIFOs. The helper adds only
its own digital JACK connections and removes them on exit.
