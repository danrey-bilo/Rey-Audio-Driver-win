# Варианты без Test Mode Windows

Проверено 03.10.2026. Текущий preview 2.7.0 использует собственный ACX с локальной
тестовой подписью и требует Test Mode. Перечисленные альтернативы пока не
реализованы его установщиком.

| Вариант | Где подходит | Ограничение |
|---|---|---|
| USB Audio Class 2.0 со встроенным драйвером Microsoft | USB без собственного сертификата драйвера ядра | Нужен другой аудиорежим Pi и проверка каналов/задержки |
| Подпись Microsoft через готового издателя | Собственный ACX для USB и LAN | Нужен согласный издатель; договорённости пока нет |
| Custom Kernel Signers | Специально подготовленные ПК | Ключи UEFI и сброс Windows; обычная установка MSI этого не заменяет |
| Пункт 7 / F7 при загрузке | Временное тестирование | Действует до перезагрузки; текущий установщик Rey этот путь не поддерживает |

## USB

В Windows есть `usbaudio2.sys` для UAC2: PCM до 32 бит. Для асинхронного выхода
нужен explicit feedback; поддержка нескольких endpoints с общим тактом ограничена.
[Документация Microsoft](https://learn.microsoft.com/en-us/windows-hardware/drivers/audio/usb-2-0-audio-drivers).

Предложение для Rey: аудио UAC2 на Pi, отдельный интерфейс управления, прежняя
служба и микшер с профилями каждой карты. Для 8×8/192 кГц/PCM32 нужно 6,144 МБ/с
в каждую сторону — 768 байт за 125 мкс. Это укладывается в номинальную полосу
High-Speed, но ещё не доказывает работу контроллера, отдельных стереопар или
физическую задержку ниже 2 мс. Нужен прототип с дескрипторами частот/форматов,
аппаратным feedback и измерением WASAPI. Нынешний FunctionFS/WinUSB не является
UAC2. Виртуальные устройства только по LAN этот системный USB-драйвер не создаёт.

## Собственный драйвер

Для обычной публикации нужна подпись Microsoft; аккаунту Hardware Dev Center
нужен действующий EV-сертификат. Если готовый издатель согласится подавать наш
драйвер, проект может обойтись без своей покупки. Такого партнёра пока нет.
[Требования Microsoft](https://learn.microsoft.com/en-us/windows-hardware/drivers/dashboard/code-signing-reqs).

[SignPath Foundation](https://signpath.org/) предлагает бесплатную подпись для
подходящих open-source проектов. Подпись EXE/MSI сама по себе не разрешает
загрузку ACX. Условия всех компонентов и возможность подачи kernel-драйвера
надо подтвердить отдельно. [Условия программы](https://signpath.org/terms.html).

Custom Kernel Signers допускает собственного подписанта: Windows 11 24H2+ с
нужными обновлениями, кроме Home; включённый Secure Boot, свой PK/KEK, подписанная
политика App Control и первоначальный сброс Windows. Нужен отдельный план
восстановления загрузки.
[Официальные требования CKS](https://learn.microsoft.com/en-us/windows/security/application-security/application-control/app-control-for-business/design/custom-kernel-signers).

F7 снимает проверку подписи только до следующей перезагрузки. Подключённый
отладчик ядра — ещё один путь разработки, но не пользовательской установки.
[Механизмы временного тестирования](https://learn.microsoft.com/en-us/windows-hardware/drivers/install/installing-an-unsigned-driver-during-development-and-test).

Добавление локального сертификата в Root/TrustedPublisher или одно отключение
Secure Boot/«Целостности памяти» не превращают новый ACX в драйвер с производственной
подписью. Установщик не ослабляет проверки скрытно. Готовый подписанный виртуальный
драйвер другого проекта годится только при подходящей лицензии и неизменённом
интерфейсе, который поддерживает нужные входы/выходы, каналы и задержку.

Установить панель/службу обычным способом, а драйвер вручную через Диспетчер
устройств технически возможно. Там выбирают INF вместе с SYS и CAT. Меняется
способ установки, но не доверие ядра: Windows может отклонить пакет или оставить
устройство с Code 52. Текущий установщик Rey устанавливает оба компонента вместе
и требует Test Mode.
[Различие установки и загрузки](https://learn.microsoft.com/en-us/windows-hardware/drivers/install/driver-signing)
· [Code 52](https://learn.microsoft.com/en-us/windows-hardware/drivers/install/cm-prob-unsigned-driver).

Для простой бесплатной USB-установки сначала стоит проверить UAC2 и сравнить
задержку с текущим транспортом. Для собственных LAN endpoints нужны партнёр
по подписи либо специально подготовленные ПК. Нынешний preview остаётся
вариантом для явного тестового режима.
