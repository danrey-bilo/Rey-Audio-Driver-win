# USB-ASIO 2.8.1: стабильность и задержка 96/192 кГц

На одной Pi5 с цифровой петлёй оба финальных контрольных профиля прошли
**175 секунд без потери PCM и опозданий отправки**. RTT p99 — около **1,53 мс**.
Реальные наблюдения Ableton на финальном коде с CPU Usage Simulator 50% также
прошли по 175 с без ошибок: 192 кГц/64 и 96 кГц/32, запас3/depth4. ASIO сообщает
сумму около 1,51 мс; это расчёт буферов.
Строгое условие «каждый измеренный RTT ниже 3 мс» **пока не выполнено**:
максимумы составили **4,3675 мс на 192 кГц** и **3,1292 мс на 96 кГц**.
Расчёт ASIO, цифровой RTT и физическая задержка ADC/DAC учитываются отдельно.

## Профили, проверенные в Ableton

| кГц | ASIO Samples | Запас ASIO, блоки | USB, пакеты | ASIO input + output, кадры | Расчёт суммы, мс |
|---:|---:|---:|---:|---:|---:|
| 192 | 64 | 3 | 4 | 160 + 129 | 1.5052 |
| 96 | 32 | 3 | 4 | 80 + 65 | 1.5104 |

Это ручные настройки контрольного host и прошедшего наблюдение Ableton. Состояние приведено ниже;
нулевые ошибки нативного теста не заменяют проверку нагруженного проекта.
На Pi используется runtime **Pi5-AUSB 0.1.1**, FIFO40 и locked memory.
Свежая установка Windows использует depth4. Сохранённые настройки сохраняются,
автоматического выбора меньшего буфера нет.

## Цифровой RTT финального установленного кода

RTT измеряется от выходного до входного callback нативного ASIO-host по PCM-маркеру.
В каждом блоке после 50 мс прогрева проверяются все восемь каналов. Разрядность —
PCM32, конфигурация — 8×8. Каждый аудиопрогон ограничен 175 секундами.

| кГц | Блок / запас / depth | Аудиопрогон, с | RTT p50 / p95 / p99 / max, мс | Drops / late frames / missing frames / overflow |
|---:|---|---:|---|---|
| 192 | 64 / 3 / 4 | 175.012 | 1.3536 / 1.4298 / 1.5280 / 4.3675 | 0 / 0 / 0 / 0 |
| 96 | 32 / 3 / 4 | 175.005 | 1.3665 / 1.4227 / 1.5199 / 3.1292 | 0 / 0 / 0 / 0 |

В каждом прогоне возвращено более 524 тысяч маркеров: повреждённых,
повторных и просроченных невозвращённых — ноль. Четыре последних маркера
при остановке находились в полёте и не объявлялись просроченными.
Обратных sample positions, ошибок MMCSS и смены USB-сессии — ноль.

| кГц | Макс. callback gap / обработка / capture age / service gap, мкс | Кадров/с | Отклонение от номинала | CPU host, одно ядро |
|---:|---|---:|---:|---:|
| 192 | 3272.900 / 42.700 / 3279.600 / 3140.900 | 191864.4 | -0.0706% | 3.553% |
| 96 | 2125.100 / 45.500 / 2131.600 / 1874.200 | 95979.0 | -0.0219% | 4.723% |

Темп рассчитан между первым и последним callback. Допуск ±1% выявляет грубое
замедление цифрового стенда; это не независимая проверка аудиотакта. CPU host
получен через GetProcessTimes: счётчик грубый и включает проверку маркеров,
поэтому не переносится на CPU Ableton. Доступ к CPU службы Windows был запрещён;
в JSON он отмечен как недоступный. Дополнительные CPU-окна Pi включают подготовку
и возврат профиля, не являются длительностью аудиопрогона и не включают IRQ/workqueue.

## Реальный Ableton

Наблюдение использует PID Ableton, неизменные generation/connection_id и профиль.
Счётчики ниже — приращения внутри окна, а не значения за всю жизнь службы.
Проверяются PCM-уровни и темп кадров. Этот тест **не измеряет RTT**.
CPU Usage Simulator задаётся пользователем; ранее незаписанное значение не угадано.

| кГц | Блок / запас | Simulator | Окно, с | Drops / late / missing / overflow | Темп относительно номинала | CPU Ableton, одно ядро | Результат / код |
|---:|---|---|---:|---|---:|---:|---|
| 192 | 32 / 4 | не записан | 175.000 | 28781 / 7844137 / 8765121 / 0 | -0.6007% | 237.054% | FAIL · до обновления defaults |
| 192 | 64 / 4 | 50% | 175.000 | 0 / 0 / 0 / 0 | -0.5113% | 121.759% | PASS · до обновления defaults |
| 192 | 64 / 3 | 50% | 175.000 | 0 / 0 / 0 / 0 | -0.3847% | 178.571% | PASS · финальный |
| 96 | 32 / 3 | 50% | 175.015 | 0 / 0 / 0 / 0 | -0.1857% | 91.055% | PASS · финальный |

CPU процесса суммирует все потоки Ableton и может превышать 100% одного ядра.
Это измеренный GetProcessTimes, а не индикатор DSP Ableton и не значение Simulator.

Нагрузка DAW существенно влияет на минимальный блок. На 192 кГц / 32 Samples
наблюдение реального Ableton выявило пропуски, хотя лёгкий native-host прошёл.
Такой профиль не предлагается как стабильный для нагруженного Ableton.
Прошедшее окно ограничено его длительностью и выбранной нагрузкой; это не гарантия
для любого проекта, сна/пробуждения или работы без временных пиков.

## Сравнение и отклонённые варианты

Результаты до финального обновления defaults используют тот же ASIO и audio-path,
но другой SHA256 службы; они сохранены отдельно, а не объявлены испытаниями финального EXE.

| кГц | Блок / запас / depth | Аудиопрогон, с | RTT p50 / p95 / p99 / max, мс | Drops / late / missing / overflow |
|---:|---|---:|---|---|
| 192 | 64 / 4 / 3 | 175.011 | 1.6623 / 1.9312 / 2.0287 / 4.0028 | 0 / 0 / 0 / 0 |
| 96 | 16 / 4 / 4 | 175.013 | 1.1350 / 1.2789 / 1.3612 / 1.9242 | 0 / 0 / 0 / 0 |
| 192 | 32 / 4 / 4 | 175.015 | 1.1488 / 1.2900 / 1.3733 / 2.0847 | 0 / 0 / 0 / 0 |
| 96 | 32 / 4 / 4 | 175.008 | 1.6342 / 1.7792 / 1.8501 / 3.3725 | 0 / 0 / 0 / 0 |
| 192 | 64 / 4 / 4 | 175.009 | 1.6477 / 1.7903 / 1.8694 / 3.2480 | 0 / 0 / 0 / 0 |

- Малые native-профили 192/32/4/depth4 и 96/16/4/depth4 дали max 2,0847 и
  1,9242 мс. Их успех не квалифицирует нагруженный Ableton.
- Большие блоки с запасом4 дали max 3,2480 и 3,3725 мс: нулевых ошибок PCM
  недостаточно для строгого RTT ниже3мс.
- Depth3 / 192 кГц / блок64 / запас4 замедлил темп примерно на 2,12% и дал
  max 4,0028 мс. Этот вариант отклонён, несмотря на нулевые счётчики PCM.
- Предварительные 30-секундные успехи сохранены. Финальные 175-секундные
  измерения показали более высокие пики; короткий тест их не исключает.

Паузы обслуживания и capture age сохранены, но без аппаратной/ETW-трассы
нельзя приписать редкий пик конкретно IRQ, контроллеру USB или планировщику.
Следующая работа для строгого максимума — локализация этих пауз; увеличение
буфера добавляет запас, но само по себе не устраняет задержку доставки.

## Изменения и проверки

- Windows выставляет IN заново сразу после переноса PCM и метаданных в локальную
  память, до микшера/IPC и ожидания OUT. Слот после resubmit больше не читается.
- Pi запускает gadget с FIFO40/reset-on-fork, CPU0 и memlock32MiB; память
  блокируется до streaming. USB IRQ на стенде остаётся FIFO50. Affinity одного
  процесса не означает, что все работы Pi выполняются одним ядром.
- Панель показывает работающий и выбранный ASIO-блок, сумму расчётных задержек,
  точные действия для применения и подсвечивает ненулевые deadline-счётчики.
  Настройки ASIO видны без прокрутки на проверенном размере окна 1120×800.
- Установщик проверяет SHA256 и заменяет только изменившиеся собственные файлы;
  идентичная DLL не переписывается. Изменённая удерживаемая DLL требует выхода из DAW.
- Windows contracts **32/32**, Pi5-AUSB **7/7 на Windows и 7/7 на Pi5**;
  Windows SDK consumer **0.1.1 EXACT — 1/1**. Финальный форматный тест — **6/6**:
  96/192 кГц × PCM16/packed24/int32, по 5 с, блок64/запас3/depth4.

Установка/обновление EXE и сохранение профиля проверены локально. Удаление,
физический hotplug/sleep/resume и системные устройства Windows — отдельные этапы.
125 мкс интервала High-Speed interrupt не равны сквозной аудиозадержке.
ADC/DAC не подключён; аналоговая петля **не измерена**. Другие частоты не
квалифицировались для цели ниже3мс. AoIP/Pi4 не обновлялись.

## Повторение и доказательства

Отключите ASIO в DAW. Нужны одна Pi5 с digital-loopback и unity mixer.
Команды возвращают ненулевой код, если строгий максимум3мс не выполнен,
даже при `functional=True` и нулевых ошибках PCM.

```powershell
python tools/test_usb_asio_profile.py --bin 'C:/Program Files/ReyAudio/USBASIO' `
  --out build/proof-192 --rate 192000 --block 64 --lead 3 --depth 4 `
  --seconds 175 --rtt-limit-ms 3 --dense-markers
python tools/test_usb_asio_profile.py --bin 'C:/Program Files/ReyAudio/USBASIO' `
  --out build/proof-96 --rate 96000 --block 32 --lead 3 --depth 4 `
  --seconds 175 --rtt-limit-ms 3 --dense-markers
python tools/test_installed_usb_asio.py --bin 'C:/Program Files/ReyAudio/USBASIO' `
  --out build/proof-formats --rates 96000 192000 --block 64 --lead 3 --depth 4
```
