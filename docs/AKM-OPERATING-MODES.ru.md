# Режимы платы AKM — разработка

[English](AKM-OPERATING-MODES.md) · [Документация](README.ru.md)

В **Rey Audio Driver → Настройки → Режим платы** на ПК доступны только:

Сборка разработки: `2.8.2-akm-dev.1`; это не опубликованный релиз 2.8.1 preview.

| Режим | Частоты нынешнего USB ASIO | Эффекты |
| --- | --- | --- |
| Аудиокарта | 44,1 / 48 / 88,2 / 96 / 176,4 / 192 кГц | Выгружаются; АЦП → ПК, ПК → ЦАП |
| Комбинированный | 44,1 / 48 / 88,2 / 96 кГц | Работают; маршруты восьми каналов задаются отдельно |

Процессор эффектов включается автоматически без USB. При повторном подключении
восстанавливаются последние режим, частота, буфер и маршруты для ПК. В вебе Pi
переключателя режимов нет. Сама плата/Linux допускают 384 кГц без эффектов, но
нынешний USB-транспорт Pi5-AUSB / Windows ASIO ограничен **192 кГц**.

Для каждого канала отдельно выбираются отправка **на ПК до/после эффектов** и
возврат **с ПК прямо на ЦАП/через эффекты**. Возврат через эффекты заменяет
источник АЦП соответствующего входа графа; вторая параллельная цепочка не
создаётся. Отправка после эффектов следует выходу графа с учётом источника
и межканальной маршрутизации пресета. До эффектов всегда берётся физический АЦП.

Перед применением останови аудиодвижок ASIO. Ограничения действуют в панели,
службе и `canSampleRate` ASIO. Команды проверяют ревизии, ожидают завершения
и читают подтверждённое состояние платы. Неопределённый результат после
тайм-аута не повторяется автоматически.

Это **интеграция управления в разработке**. Для команд нужен уже настроенный
CDC-порт Rey Effects на Pi. Панель проверяет имя продукта и протокол; без
подключения элементы управления недоступны. CDC не передаёт аудиосэмплы.

Нынешний Pi5-AUSB — отдельный WinUSB-транспорт с цифровым loopback. Он пока не
связан с PCM платы AKM. Необязательный Linux-адаптер для ALSA UAC2 также не
является адаптером Pi5-AUSB. Составное USB-устройство здесь не настраивается.
Для готовой USB-аудиокарты ещё нужны соединение ASIO-транспорта с AKM и проверка
на физическом USB. Успешная команда режима не доказывает прохождение звука.

Проверены сборка службы/DLL, **33 native-теста**, **21 проверка C#**, реальные
WPF-привязки двух режимов/восьми строк. На Pi проверен настоящий обработчик
CDC-команд через тестовый PTY — восемь запросов. Физическое USB-подключение
эти проверки не подтверждают.

Сборка разработки затем установлена поверх прежней простаивающей Windows-службы.
Подтверждены запуск, регистрация ASIO и хеши четырёх программ. На настоящей службе
проверены запрет ручного процессора, ограничение комбинированного режима 96 кГц
и отказ от 192 кГц в этом режиме. Прежний профиль аудиокарты 192 кГц и микшер
восстановлены; сохранённые настройки перешли в формат 4. Старые файлы и профиль
формата 3 сохранены отдельно до обновления.

Первая установка выявила гонку: статус службы уже «остановлена», а процесс
ещё удерживал EXE. Откат сработал. Установщик исправлен: он получает процесс
через SCM до STOP и ограниченное время ждёт его нормального завершения перед
заменой файлов. Принудительное завершение службы не применяется. Повторная
установка успешна. Это установленная сборка разработки, а не стабильный релиз
и не подтверждение аудио по USB.

Настройки службы теперь имеют формат **4**, 172 байта. Миграция форматов
1/2/3 сохраняет параметры и выбирает аудиокарту по умолчанию. Старые службы
не читают формат 4: для возврата старой версии нужна резервная копия прежних
настроек. Общая память ASIO сохраняет ABI версии 1.

Команды сборки, протокол, поведение ошибок и подробные ограничения приведены
в [английской инструкции](AKM-OPERATING-MODES.md). Linux-часть находится в
[Rey Effects Linux ARM](https://github.com/danrey-bilo/Rey-Effects-Linux-arm),
ветка `codex/operating-modes` (требуется доступ к репозиторию).
