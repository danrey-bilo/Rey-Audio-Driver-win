# Rey Audio Driver 2.8: одна USB-карта

Windows-ПО переведено только на Pi5-AUSB и одну подключённую карту Rey Audio
USB. Предварительная сборка 2.8.0 собрана и обновлена на стенде Windows/Pi5
03.10.2026. Проверки сборки, установки, настроек и форматов PCM прошли.
Номинальный темп кадров и стабильный RTT ниже 2 мс пока не подтверждены.

## Продукт и код

В активной сборке нет библиотеки AoIP, зависимости Winsock, UDP, IOCP,
сетевого поиска, правил брандмауэра и LAN-профиля. Прежние исходники,
установщик и LAN-отчёты сохранены в `archive/`, вне сборки. Репозитории AoIP,
USB-протокол Pi5-AUSB и прошивка Pi не изменялись.

Служба владеет одним `DeviceSession` и одним конкретным USB-интерфейсом.
Каталога и команды выбора карты больше нет. Одна карта подключается
автоматически. Появление второй не прерывает текущую: показывается
предупреждение. Если при запуске подключены две, служба предлагает оставить
одну, вместо произвольного выбора. Эта логика проверена моделированием
перечисления; физически на стенде одна Pi5.

В панели три страницы: **Микшер / USB / Диагностика**, сверху — одна карта.
Сохранены восемь входных и восемь выходных каналов, Master,
Mute/Solo/полярность и реальные PCM-индикаторы. Буферы USB и ASIO задаются
вручную. Привязка ASIO через настройку `DeviceId` удалена; внутренняя
проверка ID защищает владение сессией.

Исходники разделены на `src/asio`, `src/engine`, `src/audio`, `src/service`
и `src/platform`; WPF — в `apps/ReyAudioControl`. Выравнивание PCM и
USB-профиль больше не зависят от заголовков AoIP.
[Архитектура](ARCHITECTURE.ru.md).

## Установка и перенос настроек

`Rey-Audio-USB-ASIO-Setup-x64.exe` устанавливает четыре проверяемых файла:
службу, ASIO DLL, панель/трей и нативный диагностический host. Регистрируются
**Rey Audio USB ASIO** и `ReyAudioService --service --asio-only`, с автозапуском
службы и трея. Нужен UAC. INI, новый SYS/CAT, тестовый сертификат и изменение
загрузки/защиты не требуются. USB обслуживает Microsoft WinUSB; TAG не нужен.
[Установка](USB-ASIO.ru.md).

Локальное обновление завершилось успешно. SHA256 всех четырёх установленных
файлов совпали с манифестом; версия файлов — 2.8.0.0. Служба работает с
автозапуском, x64 COM/ASIO указывает на установленную DLL. Проверены путь
EXE в конфигурации SCM и имя процесса; чтение полного пути процесса
LocalSystem без прав администратора оказалось недоступно.

`HKLM\Software\ReyAudio\UsbProfile` — одно бинарное значение версии 3,
168 байт: USB и микшер. Настройки подключённой карты сохранены при
обновлении. Старые форматы 1/2 читаются для переноса; LAN-поля отбрасываются.
Сохранённые настройки ASIO остались блок64/запас3. Тесты временно меняли
запас/очередь и возвращали исходный USB-профиль. Автоподстройки нет.

SHA256 установщика:
`333592576971e0f8c37bb5ab87205a7f824c088960133de690f93702ef9fe50b`.
USB-ASIO preview публикуется отдельно от исторического пакета ACX 2.7;
прежние release assets сохранены.

Обе матрицы: 8×8, шесть частот (44,1/48/88,2/96/176,4/192 кГц),
PCM16/упакованные24/int32. Первая использовала блоки16/32/64 по частоте.
Ошибки: 44,1 кГц/16 бит, 176,4 кГц/24 бит и 192 кГц/16/32 бит.
Вторая подтверждает короткую передачу всех форматов с большим запасом render;
это не пятиминутная проверка стабильности каждого профиля.

Все аудиопрогоны: установленная ASIO COM DLL, служба SCM, нативный host
`ReyAsioProbe` и backend Pi **digital-loopback**. Реальный Ableton после этой
переделки не наблюдался. Каждый длинный аудиопрогон запрашивал 295 секунд.

## 192 кГц / PCM32 / 8×8: задержка и непрерывность

| Профиль | Длительность | Capture drops / render late / render missing frames | Цифровой RTT p50 / p95 / p99 / max, мс | Фактически кадров/с |
|---|---:|---:|---|---:|
| блок64 / запас3 / очередь USB3 | 295,015 с | 58 / 0 / 3712 | 1,2661 / 1,4903 / 1,6450 / 2,2682 | 189 305,6 |
| блок64 / запас4 / очередь USB3 | 295,008 с | 0 / 0 / 0 | 1,6286 / 1,8837 / 2,0103 / 3,5171 | 187 983,7 |
| блок64 / запас4 / очередь USB4 | 10,011 с | 1 / 0 / 64 | 1,7425 / 1,8534 / 2,0724 / 2,3545 | 190 791,7 |

Запас4/очередь3 правильно вернул все 14 440 маркеров; переполнений render,
обратных позиций и ошибок MMCSS — ноль. ASIO connection ID, PID и поколение
USB не изменились. Максимальная пауза callback host — 2,5041 мс; обработка
— 98,6 мкс; возраст capture — 2,5111 мс. CPU host: 5,71875 CPU-секунды,
1,939% одного логического ядра. Для запаса3: 18,6348 мс / 88,9 мкс / 1,3155 мс;
CPU 10,609375 с, 3,596% одного ядра. CPU службы не измерялся. Максимумы
пауз службы 1,3076/1,1603 мс могут включать прежнюю активность того же
поколения USB; счётчики host относятся к отдельному прогону.

Запас4/очередь3 прошёл непрерывность PCM, но темп кадров был
**на 2,09% ниже номинального**. Запас3 — на 1,40% ниже и с пропусками.
Короткая проверка очереди4 приблизилась к номинальному темпу, но не прошла
непрерывность. Причина не установлена: планирование Windows, completions USB
и темп цифрового backend требуют отдельной трассировки. Физический аудиотакт
не измерялся.

ASIO сообщает расчёт буферов: `input = N + depth × ceil(rate/8000)` и
`output = (lead−1) × N + 1`. Блок64/запас3/очередь3 сообщает **1,3802 мс**;
запас4/очередь3 — **1,7135 мс**. Эти числа не заменяют измерение RTT и аналоговой
петли. Новая сборка пока не квалифицирована с блоком32/16 или стабильным
RTT ниже 2 мс.

## Повторение и оставшаяся проверка

Закройте DAW; для нативных маркеров нужна одна плата и микшер без изменения PCM:

```powershell
python tools/test_installed_usb_asio.py --bin 'C:/Program Files/ReyAudio/USBASIO' `
  --out build/proof-formats --block 64 --lead 4 --depth 3
python tools/test_usb_asio_profile.py --bin 'C:/Program Files/ReyAudio/USBASIO' `
  --out build/proof-profile --seconds 295 --block 64 --lead 4 --depth 3
powershell -NoProfile -File tools/verify_usb_install.ps1 `
  -SetupDirectory build/usb-setup -Output build/install-check.json
```

Переделка на одну USB-карту завершена. Следующий аудиоэтап — номинальный темп
кадров и deadline, реальный Ableton, затем физическая петля ADC/DAC.
Системные устройства Chrome/Telegram остаются отдельным backend; USB-ASIO
EXE их не создаёт. Удаление ПО и полный физический цикл переподключения
ещё требуют проверки. Прежние результаты Ableton 2.7 — исторические данные,
они не квалифицируют новые hashes.
