# Стереопары Windows — проверка dev.7

[English](WINDOWS-PAIRS-2026-10-17.md) · **Русский**

Один установщик Rey теперь содержит неизменённый подписанный SAR 0.13.1,
службу Rey, ASIO 8×8 и микшер/трей. Автоматически появляются **Input / Output
1-2, 3-4, 5-6, 7-8 (Rey Audio)**. Внешняя программа маршрутизации,
ASIO-обёртка SAR и сетевой фильтр не нужны.

Сборка установлена на стенд, затем повторно установлена с архивом исходников
SAR. Все 11 файлов совпадают с контрольными суммами; двоичный профиль USB/микшера
сохранён без изменений. Устройство имеет статус OK, служба запускается
автоматически, в трее один процесс. После тестов возвращены 96 кГц, PCM32
и комбинированный режим.

## Результаты

| Проверка | Результат |
|---|---|
| Нативные CTest / управление платой / связи микшера / компиляция установщика | 44 / 23 / прошла / прошла |
| Синтетическая петля ядра: 6 частот × 4 пары | 24 случая по 3 с; без ошибок, повторов, пропусков и discontinuities после запуска |
| Настоящий USB/JACK, только Windows: 44,1 и 192 кГц | Четыре пары одновременно на каждой частоте, по 5 с PCM; те же нулевые счётчики |
| USB/JACK, Windows одновременно с зарегистрированным ASIO: 96 кГц | Четыре пары Windows, 20 с PCM; ASIO 45,019 с; без ошибок PCM и ASIO drops/late/missing/overflow |
| Изолированная JACK-петля | Восстановлены все 8 подключений АЦП, без ошибок восстановления и xruns |
| Простой после закрытия приложений | За 10 с ноль callbacks/отсчётов; счётчик WMI сообщил 0,0% одного логического ядра |

Маркеры проверяют номер пары, соотношение L/R и непрерывную нумерацию отсчётов.
Начальный discontinuity и число ошибок запуска сохранены в данных; из проверки
установившегося потока исключены только первые **100 мс** плавного включения
Windows. Первый тест точных отсчётов не прошёл из-за подмешивания обычных входов
АЦП в диагностический возврат. Для цифровой проверки они временно отключены;
все подключения восстановлены. Сохранённые граф, пресеты и маршруты не менялись.

## Ограничение при запуске записи

Отдельные 20-секундные проверки записи IAudioClient3 на 44,1 / 192 кГц показали
**3 / 11 начальных discontinuities** и **887 / 3876 пропущенных позиций отсчётов**.
После явно указанного **прогрева 5 с** в обеих финальных проверках за оставшиеся
15 с не было пропусков/повторов позиций и discontinuities. Непрерывность прямо
с момента Start **не подтверждена**. Прежний кандидат также зарегистрировал
пропуск двух позиций на 19,58 с; длительная стабильность остаётся открытой.
Все исходные счётчики и времена отдельных флагов сохранены в данных.

Rey готовит USB при инициализации pin с ограниченным окном прогрева 300 мс,
проверяет появление клиента раз в 1 мс и публикует общие часы WaveRT по числу
отсчётов. Дополнительных пользовательских настроек нет. Приложениям Windows
пока нужно учитывать начальные разрывы; прямой ASIO проверялся отдельно.

## Задержка прямого ASIO

Отдельный тест установленной службы dev.7 и зарегистрированной DLL прошёл
**20,018 с** на **96 кГц / PCM32 / ASIO16 / JACK32** через настоящий USB.
Вернулись **738 из 738 маркеров**; ноль потерянных, ошибочных, повторённых
маркеров, capture drops, render late/missing/overflow и обратных позиций.

| RTT, мс | p50 | p95 | p99 | max |
|---|---:|---:|---:|---:|
| По позициям PCM | 4,71875 | 4,71875 | 4,71875 | 4,71875 |
| По часам Windows | 4,6285 | 4,7377 | 4,7426 | 4,8587 |

Приросты overflow/underflow USB на Pi, JACK xruns, ошибок преобразования и
lease timeout равны нулю. Диагностический JACK-клиент не зарегистрировал xruns, включая запуск. CPU службы
ПК — **77,30% одного логического ядра**; native USB/JACK/I/O Pi —
**18,73 / 10,67 / 8,90%** одного ядра. Ableton и аналоговый АЦП/ЦАП не измерялись.

## Границы проверки

Обычный аудиодвижок Windows сообщил период **10 мс**. Результат ASIO выше
к этому пути не относится. Новые проверки системных пар через USB выполнены
в PCM32. Exclusive WASAPI, длительная DAW-нагрузка, ночной прогон, физический
hotplug, сон, удаление производственной установки и АЦП/ЦАП ещё не проверены.

Драйвер с прежней перекрёстной подписью загрузился в Windows 11 build 26300,
где Secure Boot и целостность памяти уже были отключены. Установщик их не меняет.
Другие политики подписи не проверены. Идентификаторы устройств Windows зависят
от частоты; после её смены затронутые приложения нужно переоткрыть.
