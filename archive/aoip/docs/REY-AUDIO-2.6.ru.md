# Rey Audio Driver 2.6.1 preview

Одна фоновая служба Windows управляет отдельными USB и AoIP/LAN транспортами.
Главная страница WPF-панели — **Микшер**: восемь входов и восемь выходов.
Служба и панель собираются без ASIO SDK. Поддерживается один Raspberry Pi 5.

## Компоненты

| Компонент | Назначение |
|---|---|
| `ReyAudioService.exe` | Автозапуск SCM, поиск/переподключение USB, профили, микшер, одна активная сессия |
| `ReyAudioControl.exe` | Микшер, отдельные USB/LAN страницы, ручные настройки, реальные состояния, диагностика и трей |
| USB | 8×8 PCM16/24/32; 44,1, 48, 88,2, 96, 176,4, 192 кГц; HS interrupt и асинхронный WinUSB |
| AoIP | UDP/IPv4/IOCP, ручные block/guard/packet, опциональное подавление тишины |
| ACX/KMDF | Собственный root bridge и динамический child входов/выходов, ограниченный PCM-обмен |
| EXE / MSI | Проверка ПК, локальная тестовая подпись, установка своего root, службы, трея и удаление |

Kernel-пакет собран и проверен, но **ещё не загружался и не проверялся через
WASAPI**. Локальная подпись проверена отдельно. Backend USB на Pi — цифровой
loopback; независимый аппаратный такт/feedback, ADC/DAC и физическая задержка
пока не подтверждены. Панель явно показывает недоступность аудиодрайвера.

## Установка и работа

Используйте [инструкцию EXE / MSI](INSTALL.ru.md). Новый пакет не требует INI
или PowerShell при установке. Для локально подписанного kernel-драйвера нужен
Test Mode; в EXE есть отдельная кнопка его явного включения. Установщик не
отключает Secure Boot/изоляцию ядра и не перезагружает ПК.

USB перечисляется раз в секунду без открытия занятой потоковой сессии.
При подключении проверяются стабильный DeviceId и HS-дескриптор. Поиск работает
и во время передачи. Программное переподключение gadget-службы проверено отдельно;
физическое вынимание питающего кабеля и Windows sleep/resume не квалифицированы.

Для LAN откройте трей → **AoIP / LAN**, найдите Pi или введите IPv4-адрес и
подключитесь. Настроенный LAN имеет приоритет; **Использовать USB** выбирает USB
явно. Переключение освобождает старую сессию и прерывает поток. Автоматического
LAN→USB failover нет: LAN повторяет попытки до отключения LAN или выбора USB.

USB, LAN и микшер сохраняются атомарно одним двоичным значением реестра
`HKLM\Software\ReyAudio\Profiles` в 64-битном представлении, ограниченная схема
RYS1/v2. Схема v1 читается с unity-микшером. Неактивный профиль и настройки микшера
не перезапускают текущий поток. Неверные команды не меняют настройки.
Автоматической настройки буферов нет. LAN block256/guard1536/packet32 —
консервативная начальная точка прежних цифровых тестов, а не обещание задержки.
Частота/битность LAN поступают от Pi; USB согласует собственный формат.

MSI создаёт своё правило firewall: программа службы, Private, LocalSubnet,
UDP50021. SYSTEM-служба обновляет только его порт; отсутствие/ошибка правила
отображаются в диагностике. Конечные консольные тесты firewall не меняют.
Панель работает от обычного пользователя, закрывается в трей и может завершиться
без остановки службы. [Микшер и цель физической USB-задержки <2 мс](MIXER.ru.md).

## Структура и сборка

| Каталог | Назначение |
|---|---|
| `src/service` | Кодек реестра, проверка настроек, маршрутизация/сессия, ограниченный IPC |
| `src/audio` | Gain/mute/solo/полярность и реальные уровни восьми каналов без выделений памяти |
| `src/engine` | Общий PCM-контракт, отдельные LAN и USB движки |
| `src/bridge` | Ограниченный PCM-обмен с ACX |
| `src/platform` | Планирование Windows, собственное правило firewall |
| `apps/ReyAudioControl` | WPF, модель канала, pipe-клиент, трей |
| `apps/ReyAudioSetup`, `installer` | Локальная подпись, собственное root-устройство, MSI и EXE |
| `drivers/Acx` | Root, динамический child, circuits, WaveRT |
| `tests`, `tools` | Контракты, конечные проверки, сборка и выпуск |

Нужны Windows x64, C++17, SDK/WDK, .NET Framework 4.8 и PowerShell.
Текущая экспериментальная сборка использует LLVM-MinGW / Clang с MSVC ABI;
проверка поддерживаемого MSVC/WDK toolchain ещё требуется. На пользовательском
ПК инструменты сборки и SignTool не нужны. Сборка службы:

```powershell
cmake -S . -B build/rey -G Ninja -DCMAKE_BUILD_TYPE=Release `
  -DPIAOIP_BUILD_ASIO=OFF -DPIAOIP_ENABLE_USB=ON `
  -DAOIP_SOURCE_DIR=C:/work/AoIP-lib -DPI5AUSB_SOURCE_DIR=C:/work/Pi5-AUSB
cmake --build build/rey --parallel 2
ctest --test-dir build/rey --output-on-failure
```

ACX собирается отдельно `tools/build_acx.py` с путями SDK/WDK.
Для MSI/EXE используйте официальный WiX 3.14.1:

```powershell
./tools/build_setup.ps1 -Bin build/rey/bin -Driver build/acx `
  -Wix C:/tools/wix3141 -Output build/setup
./tools/verify_setup.ps1 -Setup build/setup -Bin build/rey/bin `
  -Driver build/acx -Wix C:/tools/wix3141 -Output build/setup-inspection
```

Сборка внедряет фиксированные SYS/INF/CAT hashes в helper и выполняет ICE validation.
Проверка открывает MSI только для чтения, извлекает CAB, сравнивает все файлы и
убеждается, что EXE содержит тот же MSI. Общего закрытого ключа в пакете нет.

Локальный pipe `ReyAudio.Control.v1` не принимает удалённых клиентов. SYSTEM,
администраторы и интерактивные пользователи могут выполнять только фиксированные
проверенные команды. Запросы <1024 байт, ответы <32768 байт. PCM не проходит через
этот pipe; callback не берёт mutex менеджера. Параметры микшера публикуются атомарно,
переход gain длится 64 отсчёта без удержания сэмплов.

Конечные тесты используют отдельные двоичные `.dat` настройки с тем же кодеком,
не системный реестр. `--digital-test` разрешён только явно в конечной консольной
сессии: обычная SCM-служба не подменяет отсутствующий ACX цифровым loopback.

Лабораторный gadget Pi имеет отдельный lock. Общий владелец LAN/USB аппаратуры и
независимый такт требуют реального аудиобэкенда. Прямой kernel USB→ACX остаётся
следующим экспериментом; здесь WinUSB работает в службе.

## Проверки

- **14/14**: девять контрактов службы, включая сохранение/повреждение настроек,
  и пять DSP-проверок: точный unity PCM16/24/32, solo/mute, gain/clipping, ramp, bounds.
- **10/10** конечных проверок с реальным Pi на точном EXE релиза: поиск USB,
  отсутствие драйвера, неактивный LAN, live-микшер, неверные команды, три формата,
  пауза/переподключение. [JSON](evidence/rey-manager-msi.json).
- Ранний тест времени микшера имеет собственный hash службы:
  [JSON](evidence/rey-manager-mixer.json). Его результаты не переносятся на более
  поздний EXE с обновлением firewall.
- SYS/INF/CAT, MSI ICE validation, CAB/hashes, бесплатная локальная подпись,
  членство файлов в каталоге и отказ повреждённого SYS проверены.
  [Данные установщика](evidence/rey-installer.json).
- Реальный WPF-рендер четырёх страниц показывает все восемь каналов и состояние
  службы. Снимок сам по себе не подтверждает системные аудиоустройства.

Ранний USB-тест 299 секунд 8×8/192000/PCM32/depth3: цифровой RTT
p50/p95/p99/max **373/410/419/944,2 мкс**, без неверных пакетов, пропусков индексов
и host timeout. В отчёте указаны точные измеренные binaries отдельно от новых
сборок. [USB-отчёт](https://github.com/danrey-bilo/Pi5-AUSB/blob/v0.1.0/docs/RESULTS.ru.md).

Ещё нужны повышенная установка/repair/удаление MSI, загрузка ACX,
Verifier/cancellation, WASAPI/DAW, независимый аппаратный такт и физический
ADC/DAC loopback. Аудиопрогоны ограничены 300 секундами. Микроинтервал USB125 мкс
не объявляется измеренной задержкой звука. Pi4 не изменён.
